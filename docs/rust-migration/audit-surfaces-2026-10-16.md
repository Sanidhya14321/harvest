# UI, routes, middleware, and worker audit — 2026-10-16

This is an audit of the current working tree, including earlier uncommitted migration work. Rust does not yet own either complete product UI or the application connection services. The portable Rust terminal payload is a useful production cutover for selected primitives; it is not a terminal application, browser UI, or HTTP server. Releasing it as a complete migration would remove retained features.

## Terminal application contracts

The terminal product remains TypeScript: `packages/tui/src/tui.ts` (3,045 lines), `terminal.ts` (2,048), editor/widgets/Markdown/math/image components, application `modes/composer.ts` (1,450), `components/transcript-container.ts` (992), interactive mode/controllers, theme/editor/dialog implementations, and streaming tool-card composition.

Preserve these explicit ownership boundaries during replacement:

1. `tui.ts:117` defines immutable HistoryBatch offers with monotonic IDs and append/replay kinds; `TerminalFrameProvider` owns render/acknowledge/replay/flush operations at line 136. Semantic transcript finality must stay in the application Composer/TranscriptStore, not be guessed from row position in the low-level renderer.
2. `tui.ts:2394` computes the history-plus-viewport transaction. Complete replay bottom-splits into native history and the final viewport. `terminal.write(buffer)` occurs before updating the accepted history ID and calling `acknowledgeHistory` (`tui.ts:2545` onward). A rejected/throwing write must not retire the batch. Acceptance means accepted by the terminal output path; it must not be silently redefined to require physical terminal drain.
3. Composer acknowledges exactly the offered header/replay/transcript source (`modes/composer.ts:373`). The transcript can re-render an unacknowledged offer after a discarded frame (`transcript-container.ts:402`), and retires only the matching offered ID at line 511. Failed writes, retries, duplicate offers, resize between offer and acceptance, and shutdown flush require differential traces.
4. Preserve viewport-only diffing, both resize modes, transient alternate-screen resize rendering, anchor recovery, image placements/deletion/budget, focus/overlay input routing, and terminal restoration after hangup/crash. `terminal.ts:133` separates an actively draining oversized frame from a stalled stdout backlog; do not replace that with a raw size-only kill limit.
5. Input parsers must preserve every fragmented escape/paste/focus ordering boundary and Unicode behavior. The current TS bridge intentionally keeps some short/resumed input paths because measured N-API copying regressed them. A directly Rust-owned TUI removes that bridge cost, but full parity/performance must still be demonstrated.
6. Streaming bash previews must keep raw partial JSON through live events, transcript rebuilds, and merged result rendering; the relevant consumers include `modes/controllers/event-controller.ts`, `modes/utils/ui-helpers.ts`, `modes/components/tool-execution.ts`, and `modes/controllers/tool-args-reveal.ts`.

Start Rust frame contracts with the observable fixtures in the existing TUI frame/provider/resize tests and coding-agent transcript/composer tests, including `test/transcript-visual-consistency.test.ts`. Retain the 5,000-block p95 <10 ms and scaling <=1.3 benchmark gates. Linux local passes do not certify macOS, Windows/ConPTY, WSL, SSH, tmux, or screen.

## Protocol and lifecycle details that block naive deletion

- `wire/src/index.ts:397` fixes collaboration protocol version 3. Envelopes are four-byte big-endian peer IDs; sealed bodies are a 12-byte IV followed by AES-256-GCM ciphertext/tag. Links accept current dot forms, legacy fragment forms, `%23` handling, web wrapper links, view keys (32 bytes) and full keys plus write token (48 bytes). Crypto vectors already exist in collab-web tests.
- `collab-web/src/lib/client.ts:300` stays loading until the final snapshot chunk; host state authoritatively clears stale active tools. Transcript fetch timeout/session end is retryable null, while frame-level errors are terminal (`transcript-poll.ts`). Reconnect must not revive answered dialogs or allow view-link mutations.
- CLI and browser collab sockets currently differ: the CLI has explicit buffered-send drain handling (`collab/relay-client.ts:73` onward); the browser mirrors a 256-frame reconnect queue but sends open-socket frames directly (`collab-web/src/lib/socket.ts:72`). Unify behind bounded Rust queues and test slow peers rather than copying this divergence.
- JS Eval retirement is not isolated to an Eval tool registration. `tools/browser/tab-worker.ts:20` imports `JsRuntime` from `eval/js/shared/runtime`. Move retained browser/Python orchestration out of that dependency before deleting the JS tree. Keep page scripts required by CDP automation distinct from first-party host execution and keep historical JS cards renderable.
- `export/custom-share.ts` dynamically loads user share.ts/js/mjs handlers. Those belong in the intentional legacy interface retirement/migration map; provide the Rust/WASM share host capability rather than silently deleting custom sharing.
- `cli.ts:142` onward dispatches tiny inference, stats sync, browser tab, JS Eval thread/process, STT, TTS, memory embedding, activity and terminal-output workers, including legacy selector aliases. Retain non-retired worker protocols and startup inbox buffering in the Rust executable. Removal of JS Eval worker selectors needs the explicit removal error. SDK/test direct-module fallbacks cannot become hidden production dependencies.
- Local URI reads have realpath/containment behavior (`internal-urls/local-protocol.ts:344`), while new mutations require the deeper existing-ancestor PathPolicy check and reuse of the resolved path. Port raw-path validation and caller identity before wiring routes to filesystem operations.

## Execution units and release blockers

Add the missing automation, exports, routes, and worker capabilities to the cutover inventory. Keep retired interfaces separate from retained parity.

4. Port terminal lifecycle/writer/frame transactions and widgets, then application composer/editor/overlays/streaming cards. Run acceptance/failure/replay/resize differential traces and host matrix fixtures before deleting TS counterparts.

7. Add required Rust nextest+doctest, UI/browser production-artifact, plugin, pipeline, packaging and installed-artifact jobs. The omitted transition package suites are now included as described above. Private-package typechecking for collab-web/browser-relay/metaharness and browser acceptance against production WASM remain separate coverage work. Keep transition tests until their contracts are ported.
8. Build candidate artifacts once, validate all eight host/platform names, dashboards/workers/routes/update/rollback/checksums/signatures and detached Cargo consumers, then publish through the single gated release pipeline. Do not switch the default CLI or label a release migration-complete while any retained product surface here is unimplemented/unverified. Preserve previous-release rollback artifacts.
